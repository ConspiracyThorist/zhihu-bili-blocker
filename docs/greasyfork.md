# GreasyFork 发布资料

发脚本时把下面各段对应填进表单即可。

## 脚本

**首次发布只能用「手动输入代码」**：新建脚本页面（<https://greasyfork.org/zh-CN/scripts/new>）只有一个代码框，把 `zhihu-bili-blocker.user.js` 全文粘进去，填好下面的表单，发布。

**发布后再配自动同步**（这一步才是「从 URL 导入」）：

1. 打开已发布脚本的「管理」页 → 「同步」区块
2. 脚本代码同步地址填：

```
https://raw.githubusercontent.com/ConspiracyThorist/zhihu-bili-blocker/main/zhihu-bili-blocker.user.js
```

3. 「默认附加信息」也支持同步，地址填（格式选 **Markdown**）：

```
https://raw.githubusercontent.com/ConspiracyThorist/zhihu-bili-blocker/main/docs/greasyfork-additional-info.md
```

4. 保存。之后仓库里的脚本和附加信息都会被 GF 定期拉取

> 附加信息里如果还有别的语言版本，用「添加本地化的、同步的附加信息」按 `@name:xx` 分别配。
>
> 必须用 **raw** 地址。`github.com/.../blob/...` 返回的是 HTML 页面，同步过去会把整页源码当正文。

> 注意：GF 只在 `@version` 变大时才认为有新版本。只覆盖 GitHub Release 而不升版本号，GF 不会更新。
>
> 想让 push 立即触发同步，可再配一个 GitHub Webhook（GF 脚本管理页有现成地址），不配也能用，只是延迟长一些。

## 详细描述（直接粘贴）

```markdown
## 它做什么

把知乎热榜当成一张过滤字典：同步热榜标题，与 B 站首页推荐流里的视频标题做模糊匹配，命中就在**页面解析之前**把卡片摘掉。

摘掉的意思是卡片从头到尾不出现，不是先冒出来闪一下再消失。

## 特性

- **只看标题**：不依赖 UP 主、分区、发布时间，换账号搬运同样生效
- **四级匹配**：精确 / 包含 / bigram 相似度 / 覆盖率，能识别加前后缀、删减、等长改写的搬运
- **三档强度**：保守（默认，只拦几乎原样照搬的）/ 标准 / 激进，想精确控制还能拖滑杆
- **本地题库**：热榜标题累积为本地词库，默认保留 30 天、上限 800 条
- **远端题库**：每日从 CDN 拉取公共词库，装完即有 250+ 条可用
- **失败放行**：接口异常或数据未就绪时原样返回，不影响正常浏览
- **纯本地运行**：不上传任何数据

## 使用

装好后刷新 B 站首页，右下角会出现一个小胶囊：

- 上面显示「已拦截 / 累计」两个数字，点开看最近 5 条命中
- 觉得某条拦错了，就地「放行」，它以后不再出现
- 胶囊可以拖着挪，位置会记住
- 面板底部的「高级设置」里有：精确阈值、题库状态、远端题库源、手动刷新

## 适用范围

只处理 B 站**首页推荐流**，不含热门榜、搜索结果、播放页侧栏。

## 权限

- 两个域名：B 站首页接口、知乎热榜接口（以及拉取远端题库的两个 CDN）
- 不读取、不上传任何账号数据

## 更新日志

### 1.0.0

- 首个版本：拦截层 + DOM 兜底、三档强度、本地题库池、远端题库同步、可拖拽浮窗
```

## 发布后

1. 把脚本页的安装链接补进仓库 README 的「油猴脚本」一节
2. 首次发布后，`@namespace` 保持 `zhihu-bili-blocker` 不变，后续更新才会被识别为同一脚本
3. 版本号按仓库的 `VERSION` 走（当前 1.1.0）。改代码后如果只覆盖 Release、不改版本号，GF 侧不会自动升版，需要手动改 `build.mjs` 里的 `VERSION` 再发布
